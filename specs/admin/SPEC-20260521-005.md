# SPEC-20260521-005: OpenAPI / Swagger — Documentação Automática da API

**Status:** Aprovada

**Atualizada em:** 2026-05-21
**Autor:** análise arquitetural

## Contexto

A API NestJS não possui documentação formal de endpoints. O arquivo `docs/api/openapi.yaml` é referenciado no README mas não existe. Desenvolvedores integrando o frontend ou realizando testes precisam consultar o código-fonte para descobrir contratos da API (endpoints, request/response shapes, erros possíveis). Isso aumenta o tempo de desenvolvimento e o risco de inconsistências entre frontend e backend.

O NestJS suporta geração automática de documentação OpenAPI via `@nestjs/swagger`, sem necessidade de manter arquivos YAML manuais.

## Objetivo

Configurar `@nestjs/swagger` no NestJS para gerar automaticamente documentação interativa (Swagger UI) em `/api/docs`, disponível em ambiente de desenvolvimento e desabilitada em produção por padrão.

## Requisitos Funcionais

| ID | Requisito | Prioridade |
|----|-----------|------------|
| RF-01 | Swagger UI disponível em `GET /api/docs` em ambiente `development` | Alta |
| RF-02 | Documentação desabilitada em `production` (variável de env `SWAGGER_ENABLED=true` para override) | Alta |
| RF-03 | Todos os controllers anotados com `@ApiTags` por domínio | Alta |
| RF-04 | Todos os endpoints com `@ApiOperation` (summary) e `@ApiResponse` (200, 400, 401, 404, 429) | Alta |
| RF-05 | DTOs com `@ApiProperty` para documentar campos e tipos | Alta |
| RF-06 | Autenticação Bearer JWT documentada globalmente via `addBearerAuth` | Alta |
| RF-07 | Endpoints protegidos anotados com `@ApiBearerAuth` | Alta |
| RF-08 | Geração de arquivo `openapi.json` em build (`swagger-cli`) para `docs/api/openapi.yaml` | Média |

## Requisitos Não-Funcionais

| ID | Requisito | Métrica de Aceite |
|----|-----------|------------------|
| RNF-01 | Segurança | `/api/docs` inacessível em produção sem `SWAGGER_ENABLED=true` |
| RNF-02 | Manutenção | Decorators no código = source of truth — sem arquivos YAML manuais |
| RNF-03 | Performance | Geração do documento não impacta tempo de startup em produção |

## Critérios de Aceite

- [ ] CA-01: `GET /api/docs` retorna Swagger UI em `NODE_ENV=development`
- [ ] CA-02: `GET /api/docs` retorna 404 em `NODE_ENV=production` (sem `SWAGGER_ENABLED=true`)
- [ ] CA-03: Todos os 6 domínios (auth, vehicles, expenses, maintenance, dashboard, users) aparecem como tags separadas
- [ ] CA-04: Campo "Authorize" na UI aceita Bearer token e autentica chamadas de teste
- [ ] CA-05: Cada endpoint exibe: descrição, parâmetros, body schema, responses (incluindo 401 e 404)
- [ ] CA-06: DTOs exibem todos os campos com tipos e exemplos
- [ ] CA-07: `docs/api/openapi.yaml` gerado e commitado via script de build

## Fora de Escopo

- Não inclui: Autenticação da própria rota `/api/docs` (basic auth) — desenvolvimento local não precisa
- Não inclui: Versionamento de API (`/v1/`, `/v2/`) — não há versioning no projeto ainda
- Não inclui: Geração de SDK cliente a partir do OpenAPI schema
- Não inclui: Redoc como alternativa ao Swagger UI

## Dependências

| Tipo | Referência | Descrição |

| Biblioteca | `@nestjs/swagger@^8` | Plugin NestJS para geração OpenAPI |

## Notas Técnicas

**Instalação:**
```bash
pnpm add @nestjs/swagger swagger-ui-express --filter @nave/api
```

**Configuração em `main.ts`:**
```typescript
if (process.env.NODE_ENV !== 'production' || process.env.SWAGGER_ENABLED === 'true') {
  const config = new DocumentBuilder()
    .setTitle('Nave API')
    .setDescription('API de gestão de veículos, despesas e manutenções')
    .setVersion('1.0')
    .addBearerAuth()
    .build();
  const document = SwaggerModule.createDocument(app, config);
  SwaggerModule.setup('api/docs', app, document);
}
```

**Plugin NestJS Swagger para DTOs:** Adicionar ao `nest-cli.json` para evitar decorar cada campo manualmente:
```json
{
  "compilerOptions": {
    "plugins": ["@nestjs/swagger"]
  }
}
```
Com o plugin, campos de DTO são automaticamente inferidos sem `@ApiProperty` explícito em cada campo.

**Exemplo de anotação em controller:**
```typescript
@ApiTags('vehicles')
@ApiBearerAuth()
@Controller('vehicles')
export class VehiclesController {
  @ApiOperation({ summary: 'Listar veículos do usuário autenticado' })
  @ApiResponse({ status: 200, description: 'Lista de veículos', type: [VehicleEntity] })
  @ApiResponse({ status: 401, description: 'Token inválido ou ausente' })
  @Get()
  findAll(@UserId() userId: string) { ... }
}
```

**Geração de `openapi.yaml` em CI (opcional):**
```bash
# package.json scripts
"docs:generate": "node -e \"const app = ...; SwaggerModule.createDocument(...)\" | swagger-cli bundle -o docs/api/openapi.yaml"
```
Alternativa mais simples: adicionar endpoint `GET /api/docs-json` (gerado automaticamente pelo SwaggerModule) e fazer curl no CI.

**Env var a adicionar em `env.validation.ts`:**
```typescript
SWAGGER_ENABLED: Joi.boolean().default(false),
```
