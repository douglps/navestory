# SPEC-20260525-001: Design System — Novos Componentes UI

## 1. Contexto

O design system atual (`packages/ui`) possui componentes base bem estruturados (`Button`, `Input`, `StatsCard`, `Card`, `Table`). Para suportar o roadmap do dashboard mobile-first de gestão de frota, este spec documenta **quatro grupos de novos componentes** com exemplos de código prontos para implementação.

Todos os componentes seguem o padrão estabelecido:
- **Tailwind CSS** + variáveis OKLCH do `globals.css`
- **shadcn/ui v4** + **@base-ui/react** para primitivos headless
- **CVA** (`class-variance-authority`) para variantes
- **Mobile-first** — touch targets mínimos de 44px em mobile, compactados em `md:`

## 3. Data Display

### 3.1 KpiCard — Vertical com Sparkline

**Propósito:** exibir uma métrica chave com tendência e mini gráfico histórico. Evolui o `StatsCard` existente adicionando a camada de sparkline na base.

**Visual:**
```
┌─────────────────────────────┐
│ Combustível          ⛽     │
│                             │
│  R$ 4.820                   │
│  ↑ +12% vs mês anterior     │
│                             │
│  ▁▂▃▄▅▆▇█  (sparkline)     │
└─────────────────────────────┘
```

**Interface TypeScript:**
```tsx
interface KpiCardProps {
  title: string
  value: string | number
  unit?: string                      // ex: "km", "L", "R$"
  icon: LucideIcon
  trend?: {
    value: number                    // percentual (+/-)
    label?: string                   // ex: "vs mês anterior"
  }
  sparkline?: number[]               // array de valores históricos (6–12 pontos)
  variant?: "success" | "danger" | "warning" | "info" | "neutral"
  reverseTrend?: boolean             // ex: custo: up = bad
  loading?: boolean
  className?: string
}
```

**Exemplo de uso:**
```tsx
<KpiCard
  title="Combustível"
  value="R$ 4.820"
  icon={Fuel}
  trend={{ value: 12, label: "vs mês anterior" }}
  sparkline={[2100, 2800, 3200, 3900, 4100, 4200, 4820]}
  reverseTrend  // custo crescente = danger
/>
```

**Decisões de design:**
- Sparkline renderiza via SVG inline (sem dependência externa para um gráfico simples)
- Cor da sparkline herda o status calculado (`success` / `danger` / `warning`)
- `loading={true}` exibe skeleton com animação pulse nos 3 blocos (ícone, valor, sparkline)
- Largura: `min-w-[150px] max-w-[220px]` — grids de 2×2 no mobile funcionam com `grid-cols-2`

**Implementação sugerida para Sparkline (SVG inline):**
```tsx
function Sparkline({ values, color }: { values: number[]; color: string }) {
  const max = Math.max(...values)
  const min = Math.min(...values)
  const range = max - min || 1
  const w = 80, h = 24, step = w / (values.length - 1)

  const points = values
    .map((v, i) => `${i * step},${h - ((v - min) / range) * h}`)
    .join(" ")

  return (
    <svg width={w} height={h} className="overflow-visible">
      <polyline
        points={points}
        fill="none"
        stroke={`oklch(var(--${color}))`}
        strokeWidth="1.5"
        strokeLinecap="round"
        strokeLinejoin="round"
      />
    </svg>
  )
}
```

```tsx
interface ChartWrapperProps {

  emptyMessage?: string
```

## 4. Navigation

### 4.1 Tabs

**Propósito:** navegação contextual entre views (ex: "Veículos / Despesas / Manutenções" no detalhe de um veículo).

**Interface TypeScript:**
```tsx
interface TabsProps {
  items: {
    value: string
    label: string
    icon?: LucideIcon
    badge?: string | number         // ex: contagem de alertas
    disabled?: boolean
  }[]
  defaultValue?: string
  value?: string
  onValueChange?: (value: string) => void
  variant?: "default" | "pills" | "underline"
}
```

**Variante `underline` (padrão no dashboard):**
```
  Visão Geral   Despesas(3)   Manutenções
  ───────────   ────────────
  ^ativo        ^ativo
```

**Variante `pills`:**
```
 [Visão Geral] [Despesas 3] [Manutenções]
  ─────────────
  ^ativo (bg preenchido)
```

**Exemplo de uso:**
```tsx
<Tabs
  variant="underline"
  defaultValue="overview"
  items={[
    { value: "overview", label: "Visão Geral", icon: LayoutDashboard },
    { value: "expenses", label: "Despesas", badge: 3 },
    { value: "maintenance", label: "Manutenções", icon: Wrench },
  ]}
/>
```

### 4.2 Breadcrumb

**Propósito:** rastreabilidade de navegação em telas aninhadas.

**Interface TypeScript:**
```tsx
interface BreadcrumbProps {
  items: {
    label: string
    href?: string                   // undefined = item atual (sem link)
    icon?: LucideIcon
  }[]
  maxItems?: number                 // colapsa itens do meio com "..." quando excede
}
```

**Visual:**
```
Frota  /  Veículos  /  ABC-1234  /  Despesas
  🏠        🚗           📋
```

**Comportamento mobile:** quando `maxItems` é excedido, colapsa itens intermediários:
```
Frota  /  ...  /  Despesas
```

**Exemplo de uso:**
```tsx
<Breadcrumb
  items={[
    { label: "Frota", href: "/fleet", icon: Home },
    { label: "Veículos", href: "/fleet/vehicles" },
    { label: "ABC-1234", href: "/fleet/vehicles/abc-1234" },
    { label: "Despesas" },          // item atual, sem link
  ]}
  maxItems={3}
/>
```

### 4.3 Steps — Wizard Horizontal

**Propósito:** indicador de progresso em fluxos de múltiplas etapas (ex: cadastro de veículo, onboarding).

**Layout selecionado:** horizontal com conectores.

**Visual:**
```
  ●──────────●──────────○──────────○
 Dados      Veículo   Revisão   Confirmar
  ✓          atual
```

**Interface TypeScript:**
```tsx
interface StepsProps {
  steps: {
    id: string
    label: string
    description?: string
    icon?: LucideIcon
  }[]
  currentStep: number               // índice 0-based
  completedSteps?: number[]         // índices concluídos
  onStepClick?: (index: number) => void  // permite navegar para passos concluídos
}
```

**Estados de cada passo:**
- `completed` — círculo preenchido com ✓, cor `success`
- `current` — círculo com borda `primary`, label em bold
- `upcoming` — círculo vazio, label em `muted`
- `error` — círculo com ✗, cor `danger`

**Exemplo de uso:**
```tsx
<Steps
  steps={[
    { id: "personal", label: "Dados", description: "Informações pessoais" },
    { id: "vehicle", label: "Veículo", description: "Dados do veículo" },
    { id: "review", label: "Revisão" },
    { id: "confirm", label: "Confirmar" },
  ]}
  currentStep={1}
  completedSteps={[0]}
  onStepClick={(i) => setStep(i)}
/>
```

### 5.3 DateRangePicker

**Propósito:** seleção de período para filtros de relatórios (ex: "despesas de Jan a Mar").

**Visual mobile (dois inputs empilhados):**
```
┌──────────────────┐  ┌──────────────────┐
│  📅 01/01/2026  │  │  📅 31/03/2026  │
│  Data inicial   │  │  Data final     │
└──────────────────┘  └──────────────────┘
```

**Interface TypeScript:**
```tsx
interface DateRangePickerProps {
  value?: { from: Date; to?: Date }
  onValueChange: (range: { from: Date; to?: Date } | undefined) => void
  placeholder?: string
  disabled?: boolean
  minDate?: Date
  maxDate?: Date
  presets?: {
    label: string
    range: { from: Date; to: Date }
  }[]                               // ex: "Últimos 30 dias", "Este mês"
  error?: string
}
```

**Presets padrão para frota:**
```tsx
const FLEET_PRESETS = [
  { label: "Últimos 7 dias", range: last7Days() },
  { label: "Últimos 30 dias", range: last30Days() },
  { label: "Este mês", range: currentMonth() },
  { label: "Mês anterior", range: previousMonth() },
  { label: "Este ano", range: currentYear() },
]
```

**Exemplo de uso:**
```tsx
<DateRangePicker
  value={dateRange}
  onValueChange={setDateRange}
  presets={FLEET_PRESETS}
  maxDate={new Date()}
  error={errors.dateRange?.message}
/>
```

## 6. Feedback

### 6.1 Alert

**Propósito:** mensagens de feedback contextual (inline em formulários ou seções de página).

**Variantes:**
```
[ℹ]  Info:    [ borda esquerda azul  ] fundo info-pastel
[✓]  Success: [ borda esquerda verde ] fundo success-pastel
[⚠]  Warning: [ borda esquerda laranja ] fundo warning-pastel
[✗]  Error:   [ borda esquerda vermelha ] fundo danger-pastel
```

**Visual:**
```
┌──────────────────────────────────────────────┐
│ ⚠  Atenção                                   │
│    A manutenção do ABC-1234 está vencida há  │
│    3 dias. Atualize o registro.              │
│                          [Ver veículo]       │
└──────────────────────────────────────────────┘
```

**Interface TypeScript:**
```tsx
interface AlertProps {
  variant: "info" | "success" | "warning" | "error"
  title?: string
  description: string
  action?: {
    label: string
    onClick: () => void
  }
  onDismiss?: () => void            // botão ✕ opcional
  icon?: LucideIcon                 // override do ícone padrão
  className?: string
}
```

**Exemplo de uso:**
```tsx
<Alert
  variant="warning"
  title="Manutenção vencida"
  description="ABC-1234 está com revisão atrasada há 3 dias."
  action={{ label: "Ver veículo", onClick: () => router.push("/vehicles/abc") }}
  onDismiss={() => setDismissed(true)}
/>
```

### 6.2 Toast

**Propósito:** notificações temporárias e não-bloqueantes (confirmações de ação, erros de request).

**Posição:** canto inferior direito (desktop) / topo centralizado (mobile).

**Visual:**
```
              ┌──────────────────────────────┐
              │  ✓  Veículo salvo com sucesso │
              │                           ✕  │
              └──────────────────────────────┘
```

**Interface TypeScript:**
```tsx
interface ToastOptions {
  variant?: "default" | "success" | "error" | "warning" | "info"
  title: string
  description?: string
  duration?: number                 // ms, padrão 4000
  action?: {
    label: string
    onClick: () => void
  }
}

// Hook de uso:
const { toast } = useToast()

toast({
  variant: "success",
  title: "Despesa registrada",
  description: "R$ 180,00 adicionado em Combustível",

})
```

**Implementação:** usar `sonner` (já é dependência comum em shadcn) ou composição nativa com `@base-ui/react/toast` quando disponível.

## 7. Padrões de Listagem

### 7.1 Layout de Tabela em 2 Linhas (Two-Row Table)

**Propósito:** todas as tabelas de listagem do sistema usam um layout compacto de 4 colunas com conteúdo empilhado verticalmente na célula central, em vez de linhas longas com muitas colunas.

**Estrutura padrão:**

| Coluna | Conteúdo |
|--------|----------|
| **Data/Vencimento** | Data principal + data secundária (vencimento, conclusão) |
| **Detalhes** | Linha 1: entidade principal (veículo, etc.) · Linha 2: badges + descrição + tags |
| **Valor/Custo** | Valor monetário alinhado à direita |
| **Ações** | Botões de edição/exclusão (80px) |

**Visual:**
```
┌──────────┬─────────────────────────────────────┬──────────┬─────┐
│ Data     │ Detalhes                            │    Valor │     │
├──────────┼─────────────────────────────────────┼──────────┼─────┤
│ 15/06/26 │ Hilux SR5 (ABC-1234)                │  R$ 350  │ ··· │
│          │ [Combustível] Posto Shell · via Man. │          │     │
├──────────┼─────────────────────────────────────┼──────────┼─────┤
│ 14/06/26 │ Gol G8 (DEF-5678)                   │  R$ 120  │ ··· │
│          │ [Manutenção] Troca de óleo           │          │     │
└──────────┴─────────────────────────────────────┴──────────┴─────┘
```

**Regras de implementação:**
- Todas as células usam `align-top` para alinhar à primeira linha visual
- Zebra striping: linhas ímpares (índice 1, 3, 5...) recebem `bg-muted/15`
- A célula "Detalhes" empilha conteúdo com `mt-1` entre as duas linhas visuais
- Badges, descrições e tags na segunda linha usam `flex items-center gap-2`
- Hover: `hover:bg-muted/50 transition-colors`

**Exemplo de código:**
```tsx
{items.map((item, idx) => (
  <TableRow className={cn(
    "hover:bg-muted/50 transition-colors",
    idx % 2 === 1 && "bg-muted/15",
  )}>
    <TableCell className="align-top">...</TableCell>
    <TableCell className="align-top">
      <div>{/* Linha 1: info principal */}</div>
      <div className="flex items-center gap-2 mt-1">
        {/* Linha 2: badges + descrição + tags */}
      </div>
    </TableCell>
    <TableCell className="text-right align-top">...</TableCell>
    <TableCell className="align-top">...</TableCell>
  </TableRow>
))}
```

**Páginas que usam este padrão:**
- `/expenses` (tab "Todas" e accordion "Por veículo")
- `/fines`
- `/maintenance`
- `/recurring-costs`

### 7.2 Indicador de Filtros Ativos (Active Filter Indicator)

**Propósito:** feedback visual imediato quando filtros estão aplicados em uma listagem.

**Visual:**
```
Sem filtros:                        Com filtros:
┌──────────────────────────┐        ┃ ┌──────────────────────────┐
│ 🔍 Filtros: [Todos ▾]   │        ┃ │ 🔍 Filtros: [Jan 26 ▾]  │  ← bg-primary/5
└──────────────────────────┘        ┃ └──────────────────────────┘
                                    ↑ border-l-2 border-l-primary
```

**Regras de implementação:**
- Wrapper do filtro recebe `rounded-lg px-3 py-2 transition-colors`
- Filtros ativos: `border-l-2 border-l-primary bg-primary/5`
- Sem filtros: `border-l-2 border-l-transparent` (reserva espaço, evita layout shift)
- Usar variável booleana existente (`hasFilters`, `current`, etc.) para alternar

**Componentes que usam este padrão:**
- `ExpenseFilters` — `hasFilters`
- `UpcomingFilters` — `hasFilters`
- `MaintenanceStatusFilter` — `current`

**Variações por contexto:**
| Contexto | Ícone sugerido | CTA |
|---|---|---|
| Lista de veículos | `Car` | "Adicionar veículo" |
| Despesas | `Receipt` | "Registrar despesa" |
| Manutenções | `Wrench` | "Agendar manutenção" |
| Busca sem resultado | `SearchX` | "Limpar filtros" |
| Erro de carregamento | `AlertCircle` | "Tentar novamente" |
