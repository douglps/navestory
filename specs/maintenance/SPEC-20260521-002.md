# SPEC-20260521-002: Alertas de Manutenção por Email

**Status:** Aprovada
**Criada em:** 2026-05-21
**Atualizada em:** 2026-05-21
**Autor:** análise arquitetural
**Revisores:** —

---

## Contexto

O PRD (RF-006) exige que usuários recebam alertas 7 dias antes de manutenções agendadas. A tabela `maintenances` já possui a coluna `alert_sent BOOLEAN DEFAULT FALSE`, indicando que a feature foi planejada mas não implementada. Sem alertas, usuários esquecem manutenções críticas — o que vai contra a proposta de valor central do navestory ("evitar esquecimentos críticos").

Estado atual: nenhum mecanismo de envio de email existe no sistema.

## Objetivo

Implementar um job agendado (Supabase pg_cron + Edge Function) que, uma vez por dia, identifica manutenções com `scheduled_date = HOJE + 7 dias` e `alert_sent = false`, envia um email de alerta ao usuário e marca `alert_sent = true`.

## Critérios de Aceite

- [ ] CA-01: Job executa diariamente às 08:00 BRT (11:00 UTC)
- [ ] CA-02: Usuário recebe email quando `scheduled_date = TODAY + 7` e `alert_sent = false`
- [ ] CA-03: `alert_sent` muda para `true` após envio — reexecução do job não reenvia
- [ ] CA-04: Manutenções com `deleted_at IS NOT NULL` não geram alertas
- [ ] CA-05: Email contém placa e modelo do veículo, descrição da manutenção e data agendada
- [ ] CA-06: Falha no envio de email de um registro não impede o processamento dos demais
- [ ] CA-07: Evento `MAINTENANCE_ALERT_SENT` registrado em `audit_logs`

## Fora de Escopo

- Não inclui: Push Notifications nativas (definido como OUT no PRD — Fase 2)
- Não inclui: SMS ou WhatsApp
- Não inclui: Configuração de horário de alerta por usuário (Fase 2)
- Não inclui: Alertas para manutenções com menos de 7 dias (urgência — Fase 2)

## Notas Técnicas

**Arquitetura do job:**

```
pg_cron (diário 11:00 UTC)
  └─ HTTP POST → Edge Function `send-maintenance-alerts`
       ├─ SELECT maintenances WHERE scheduled_date = NOW() + 7d AND alert_sent = false AND deleted_at IS NULL
       ├─ Para cada manutenção:
       │    ├─ auth.admin.getUserById(user_id) → email
       │    ├─ Resend.emails.send({to: email, subject, html})
       │    ├─ UPDATE maintenances SET alert_sent = true WHERE id = ?
       │    └─ INSERT audit_logs (MAINTENANCE_ALERT_SENT)
       └─ Retorna: { sent: N, errors: M }
```

**Alternativa descartada — NestJS cron:** Requereria que o backend NestJS esteja sempre rodando, adicionando complexidade de infra. A Edge Function + pg_cron é mais simples e nativa ao Supabase.

**Template de email:** HTML simples com Tailwind Inline para compatibilidade máxima. Variáveis: `{{user_name}}`, `{{maintenance_description}}`, `{{scheduled_date}}`, `{{vehicle_plate}}`, `{{vehicle_model}}`, `{{app_url}}`.

**Tratamento de falhas:** `UPDATE alert_sent = true` só ocorre após confirmação de envio (`Resend` retorna `id`). Se falhar, o registro permanece `alert_sent = false` e será retentado no próximo ciclo do job.

**Variáveis de ambiente necessárias:**

- `RESEND_API_KEY` — chave da API do Resend
- `SUPABASE_SERVICE_ROLE_KEY` — já existente
- `NEXT_PUBLIC_APP_URL` — para link no email
