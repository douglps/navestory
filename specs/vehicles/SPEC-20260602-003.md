# SPEC-20260602-003: Grupos de Veículos

**Status:** Aprovado
**Criada em:** 2026-06-02
**Atualizada em:** 2026-06-02
**Autor:** douglps
**Revisores:** —

## Contexto

Usuários que gerenciam frotas com múltiplos veículos (persona P-002 — Ana, Gestora de Frota Pequena) precisam segmentar e analisar subconjuntos da frota sem selecionar cada veículo individualmente. Exemplos de uso: "motos de entrega", "frota São Paulo", "veículos em revisão periódica".

O sistema Em Foco (SPEC-20260602-001) já suporta o modo de contexto `group`, mas a feature de criação e gerenciamento de grupos nunca teve spec formal. Este documento retroativamente formaliza os requisitos do domínio de grupos de veículos.

---

## Objetivo

Permitir que o usuário crie grupos nomeados e coloridos, associe veículos da sua frota a cada grupo, e use esses grupos como filtro de contexto em todo o dashboard (despesas, manutenções, KPIs).

## Critérios de Aceite

- [ ] CA-01: `createGroup({ name: "Motos", color: "#ef4444" })` cria grupo e retorna `{ ok: true, data: { id: "..." } }`
- [ ] CA-02: `createGroup({ name: "", color: "#ef4444" })` retorna `{ ok: false, error: "Nome obrigatório" }`
- [ ] CA-03: `createGroup({ name: "X", color: "red" })` retorna `{ ok: false, error: "Cor inválida — use hex de 6 dígitos" }`
- [ ] CA-04: `setGroupMembers({ groupId, vehicleIds: [...201 ids] })` é rejeitado pela validação Zod com erro de máximo
- [ ] CA-05: `setGroupMembers` com veículo de outro usuário na lista — esse veículo não aparece como membro após a operação
- [ ] CA-06: `setGroupMembers` com veículo com `deleted_at` na lista — esse veículo não aparece como membro
- [ ] CA-07: Após `deleteGroup(groupId)`, query em `vehicle_group_members` para aquele `group_id` retorna zero registros
- [ ] CA-08: `updateGroup({ id, name: "Frota SP" })` para grupo de outro usuário não altera nenhum registro
- [ ] CA-09: Ativar grupo no `FleetAside` → URL contém `?groupId=<uuid>` e página de despesas filtra apenas por veículos daquele grupo
- [ ] CA-10: Excluir grupo ativo → store limpa `activeGroupId`, URL perde o param `groupId`, nenhum toast de erro é exibido

## Fora de Escopo

- Grupos aninhados (hierarquia de grupos)
- Compartilhamento de grupo entre usuários

- Audit log de operações de grupo (não implementado — diferente de veículos/despesas)
- Histórico de membros anteriores de um grupo (replace-all não mantém histórico)

## Notas Técnicas

### Hard-delete de grupos vs. soft-delete de veículos
Grupos usam hard-delete — a Server Action `deleteGroup` executa `.delete()` diretamente. Isso contrasta com veículos (R-VEH-01, soft-delete). A remoção de `vehicle_group_members` é garantida pela FK `ON DELETE CASCADE` no banco, não por lógica de aplicação.

### Replace-all em `setGroupMembers`
A operação é não-atômica: primeiro apaga todos os membros (`.delete().eq('group_id', ...)`), depois insere os novos. Uma falha no insert deixa o grupo sem membros — não há rollback. Melhoria futura: envolver em uma RPC Supabase transacional.

### Limite de veículos no `FleetAside`
O `FleetAside` carrega no máximo 20 veículos (`.limit(20)`) para o seletor de membros. Usuários com mais de 20 veículos não verão todos os veículos no formulário inline de grupo — limitação conhecida do MVP.

### Ausência de API REST — superado, ver changelog 2026-07-13
~~Grupos são gerenciados exclusivamente via Server Actions do Next.js (`group-actions.ts`), sem endpoints REST no NestJS.~~ Na implementação (T2.2), optou-se por seguir o padrão REST + TanStack Query já estabelecido em SPEC-20260602-002 e consolidado em `docs/architecture/overview.md`, em vez de Server Actions. Ver `VehicleGroupsModule` em `apps/api/src/modules/vehicle-groups/`.

### Paleta preset
`PRESET_GROUP_COLORS` está exportada do pacote `@nave/validators` — isso cria um acoplamento entre a camada de validação e a apresentação (8 cores hardcoded). Alternativa futura: mover para um arquivo de constantes de UI.

## Regras de Domínio Referenciadas

> Ver `specs/RULES.md` para definição completa.

| ID | Resumo |
|----|--------|
| R-GRP-01 | Máximo 200 veículos por grupo — validado pelo schema Zod em `setGroupMembersInputSchema` |
| R-GRP-02 | `setGroupMembers` usa replace-all; histórico de membros anteriores não é preservado |
| R-GRP-03 | Apenas veículos ativos (`deleted_at IS NULL`) do próprio usuário podem ser membros de um grupo; veículos inválidos são descartados silenciosamente |
| R-GRP-04 | Exclusão de grupo é hard-delete; membros são removidos por cascade FK, não por lógica de aplicação |
| R5 | Soft-delete em veículos; grupos não têm `deleted_at` |
| R-CTX-02 | Contexto `group` persiste em localStorage; limpo no logout |
